# 控制流与复杂度样例

本目录提供 3 组用于演示“控制流与复杂度度量”模块的 Java 样例。  
建议在前端“控制流与复杂度”页面中分别导入这些样例，以验证系统在基础计算、决策点识别和项目级分析三个方面都能稳定工作。

## 样例 1：基础复杂度计算

文件：

- `01_BasicComplexityDemo.java`

这个样例用于证明系统能够正确完成**基础圈复杂度计算**。

建议重点观察：

- `straightLine(...)`：顺序结构，复杂度应接近 `1`
- `singleIf(...)`：包含一个 `if`，复杂度应比顺序结构高
- `loopAndBranch(...)`：同时包含 `for` 和 `if`，复杂度继续上升

这个样例主要证明：

1. 系统能识别最基本的顺序、分支、循环结构
2. 不同控制结构会让复杂度呈现合理递增
3. 方法级结果、Top 方法和风险等级联动正常

## 样例 2：决策点识别细节

文件：

- `02_DecisionRecognitionDemo.java`

这个样例用于证明系统不只是“数 if 的个数”，而是能识别更完整的**决策点类型**。

建议重点观察：

- `&&`、`||`
- `else if`
- `switch / case`
- 三目运算符 `?:`
- `catch`
- `while`

这个样例主要证明：

1. 系统可以识别多种 McCabe 决策点来源
2. 方法的 `decisionPoints` 列表是可解释的，不是黑盒分数
3. 控制流图与决策点统计能够相互印证

## 样例 3：项目级多文件分析

文件：

- `03_OrderApprovalService.java`
- `03_DiscountPolicy.java`
- `03_RefundWorkflow.java`

这 3 个文件要**一起上传**，作为一个小型项目样例使用。  
它用于证明系统具备**多文件、类级汇总、方法级对比和高风险定位**能力。

建议重点观察：

- `OrderApprovalService.approve(...)`：多层条件嵌套，复杂度较高
- `DiscountPolicy.calculateDiscount(...)`：中等复杂度的业务规则方法
- `RefundWorkflow.resolve(...)`：带 `switch` 的流程方法

这个样例主要证明：

1. 系统可以在项目维度汇总多个 Java 文件
2. 可以输出类级汇总和方法级明细，而不是只看单个方法
3. 可以定位“哪个类/哪个方法最复杂、最需要测试或重构”

## 如何用这 3 组样例证明系统完备

这 3 组样例合起来，正好覆盖了控制流与复杂度模块最关键的三种能力：

1. **基础正确性**：样例 1 证明圈复杂度计算是成立的
2. **规则完整性**：样例 2 证明系统能识别多种决策点，而不是简单计数
3. **工程实用性**：样例 3 证明系统可以处理更接近真实项目的多文件分析场景

因此，这三组样例可以共同说明：  
我们的系统不仅能算复杂度，而且能解释复杂度、定位风险，并支持项目级使用场景，具备较好的完整性和实用性。
