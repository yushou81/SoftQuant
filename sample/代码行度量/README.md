# 代码行度量样例说明

本目录包含 3 组用于演示代码行度量模块的样例。

## 样例 1：`01_BasicLocDemo.java`

用途：
- 验证基础 LoC 统计是否准确。
- 重点观察物理行、代码行、纯注释行、空白行、混合行和逻辑行。

建议演示点：
- 文件中同时包含空白行、单行注释、块注释和行尾注释。
- 应能看到 `mixedLines` 大于 0。
- 由于是结构清晰的 Java 方法，`logicalLines` 也应被正确统计。

## 样例 2：`02_CommentEdgeCases.java`

用途：
- 验证系统不会把字符串或字符字面量中的注释符号误判为真实注释。
- 重点证明“复杂边界情况仍能正确统计”。

建议演示点：
- 文件里有 `"http://"`、`"/* not a comment */"`、`'#'`、`'/'` 等内容。
- 系统应只统计真正的注释，不应把字符串里的 `//`、`/* */` 当成注释。
- 这个样例最适合说明我们的扫描器不是简单正则匹配。

## 样例 3：多语言项目组合

文件：
- `03_OrderService.java`
- `03_metrics_report.py`
- `03_native_stats.cpp`

用途：
- 验证系统支持多语言、多文件联合统计。
- 重点观察文件级明细、语言级汇总和项目级总览。

建议演示点：
- 同时上传这 3 个文件。
- 应能看到 Java、Python、C++ 三种语言的分类汇总。
- Java 文件会给出 AST 逻辑行统计，其他语言会按文本扫描统计。

## 如何用这 3 组样例证明系统完备

1. `01_BasicLocDemo.java` 证明基础行分类功能完整。
2. `02_CommentEdgeCases.java` 证明复杂注释边界处理可靠。
3. `03_*` 组合样例证明系统具备多语言、多文件、项目级汇总能力。

三组样例合在一起，可以覆盖：
- 基础统计准确性
- 边界场景鲁棒性
- 实际项目场景适用性
